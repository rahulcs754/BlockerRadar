Why teams use it

Shorter standups

Updates are already written. The meeting is only for the blockers.

Blockers come out early

A PR waiting two days for review or a red main shows up with a link and the person who can fix it.

Nobody types an update

Other standup bots ask questions. BlockerRadar reads GitHub and your tracker.

Fair to remote teams

Wait time counts working days in your timezone, so Monday mornings are not full of false alarms.

Safe by design

Read-only on GitHub, Jira and Linear. Tokens stay in your Actions secrets. The only write is the Slack post.

Free and self-hosted

A GitHub Action plus one YAML file. No dashboard, no seat pricing, no data leaving your org.

How to set it up

  1. Create tokensA read-only GitHub fine-grained token, a Slack incoming webhook, and a Jira API token or Linear API key if you use one.
  2. Add blockerradar.ymlList your repos and your team: GitHub login, tracker email and Slack id for each person. 
    timezone: Asia/Kolkata
repos: [acme/web, acme/api]
tracker: { type: jira, baseUrl: https://acme.atlassian.net, project: FS }
team:
  - { name: Asha, github: asha-dev, tracker: asha@acme.com, slack: U012ABC }
  3. Try a dry runRun the CLI with --dry-run to see the digest in your terminal. Nothing is posted.
  4. Schedule itAdd the secrets and a workflow with uses: rahulcs754/BlockerRadar@main on a weekday cron. The digest lands in Slack every morning.
